# 설계 결정 기록 (ADR)

형식: 배경 → 결정 → 결과. 바꾸고 싶으면 새 항목을 추가하고 이전 항목에 "대체됨" 표시.

## ADR-1 로컬 단일 사용자, 인증 없음
- 배경: 개인 PC(Windows)에서 혼자 쓰는 연습 도구. 파일 시스템 접근이 핵심 요구.
- 결정: 서버를 `127.0.0.1` 에 바인딩하고 인증을 두지 않는다. 다중 사용자는 범위 밖.
- 결과: 구현 단순. 공유 망 노출 시 위험 → FAQ 에 경고, `HOST` 변경은 사용자 책임.

## ADR-2 의존성 최소화, 프런트 라이브러리 0
- 배경: 이후 유지보수는 "자체 AI" 가 맡는다. 빌드 파이프라인·프레임워크 버전 관리는 부담.
- 결정: 서버 express + 공식 AI SDK 3종만. 프런트는 순수 ES 모듈, 마크다운 렌더러·에디터 자체 구현.
- 결과: 오프라인 동작, 읽기 쉬운 코드. 대가: 에디터 기능은 소박함(execCommand). 새 패키지는 꼭 필요할 때만, 이 문서에 기록.

## ADR-3 파일 기반 저장소
- 배경: 백업·이동·수동 편집이 쉬워야 하고 설치가 단순해야 한다.
- 결정: `data/` 아래 JSON + 원본 파일. 문제집 폴더 자체가 교환 형식.
- 결과: DB 없음. 동시 쓰기 보호 없음(단일 사용자 전제). 쓰기는 임시 파일 후 rename 으로 원자성 확보.

## ADR-4 공식 SDK 사용 (raw fetch 대신)
- 배경: 각 API 의 스트리밍·재시도·오류 형식이 다르고 자주 바뀐다.
- 결정: Anthropic/OpenAI/Google 공식 SDK 를 쓰고 얇은 어댑터로 정규화. OpenAI 호환 서버(OpenCode Zen, Ollama)는 OpenAI SDK + baseURL.
- 결과: 유지보수 시 SDK 업데이트로 API 변화를 흡수. 어댑터 인터페이스는 `architecture.md`.

## ADR-5 SSE over POST
- 배경: 채팅/생성은 스트리밍이 필요하고 요청 본문이 크다(답안·컨텍스트).
- 결정: `fetch` POST + `text/event-stream` 응답, 클라이언트는 ReadableStream 파싱. WebSocket 은 불필요.
- 결과: 프록시 친화적, 구현 단순. 클라이언트 중단은 `res.on('close')` 로 감지(`req` close 는 본문 수신 후 즉시 발생하므로 쓰지 않음).

## ADR-6 Claude 호출 규약
- 결정: thinking 파라미터 미전송(adaptive 기본), 샘플링 파라미터 미전송, Claude 5 세대에는 `fallbacks:'default'`(베타 헤더) 기본 적용 + 400 시 일반 호출 재시도, 모델 ID 에 날짜 접미사 금지.
- 결과: 최신 모델에서 400 을 피하고 거부 응답을 줄인다. 규약은 `providers.md` 에 상세.

## ADR-7 참고자료는 텍스트만 프롬프트에 포함
- 배경: PDF/Office 추출은 의존성과 품질 문제가 크다.
- 결정: 1차 버전은 텍스트 확장자만 본문 전달, 나머지는 파일명·설명만. UI 와 문서에 명시.
- 결과: 사용자는 md/csv 로 변환해 올린다. 추출기 추가는 백로그(`maintenance.md`).

## ADR-8 한국어 우선
- 결정: UI, 오류 메시지, 문서, 코드 주석을 한국어로. 식별자는 영어.
- 결과: 대상 사용자(국내 업무 교육)에 맞춤. 다국어는 백로그.
