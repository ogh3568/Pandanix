# 결제 시스템 구성 및 변경 이력

## 1. 구성 요약
- 앱/웹 → API 게이트웨이 → `order-api` → `pay-gateway` → 외부 PG사 2곳(카드·간편결제)
- `pay-gateway`: 컨테이너 6대, 컨테이너당 PG 연결 커넥션 풀 운영(v3.7.4 기준 최대 200)
- 결제 실패 시 `order-api` 는 주문서를 '결제대기' 로 30분 유지 후 자동 취소

## 3. 배포 정책(현행)
- 운영 배포는 2인 이상 코드 리뷰 원칙이나, '긴급·일정 대응' 시 1인 리뷰 허용(사후 보고).
- 대형 프로모션 전후 24시간은 **배포 동결 권고**(강제 아님). v3.8.0 은 프로모션 오픈에 간편결제를 맞추기 위해 예외 배포.
- 부하 테스트는 '트래픽 영향 변경' 에만 필수 — 설정 파일 변경은 대상인지 기준이 모호함.
- 카나리 배포 도구는 9월 도입, 결제 서비스는 아직 미적용.

## 4. 모니터링 경보 정책(현행)
- 1차(오류율 5%): 팀 공용 메일 / 2차(오류율 30%): 온콜 호출기
- 경보 정책은 2024년 이후 재검토 이력 없음.
