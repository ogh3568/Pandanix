# 주문 테이블(dw.orders) 데이터 정의서

관리: 데이터플랫폼팀 / 원천: 주문관리시스템(OMS) / 적재: 매일 01:00 배치(전일분)

## 1. 컬럼 규칙

| 컬럼 | 타입 | 필수 | 규칙 |
|---|---|---|---|
| order_id | 문자 | Y | 기본키, 중복 불가. 'O' + 8자리(YYMMDD + 일련번호 2자리) |
| order_date | 날짜 | Y | `YYYY-MM-DD` 형식 |
| cust_id | 문자 | Y | 'C' + 5자리. 비회원 주문도 임시 ID(C9xxxx) 발급 |
| channel | 코드 | Y | `WEB`, `APP`, `STORE` 중 하나(대문자) |
| sku | 문자 | Y | 상품코드 'SK-' + 3자리 |
| qty | 정수 | Y | 1 이상 |
| unit_price | 정수 | Y | 원 단위, 0 초과 |
| discount | 정수 | Y | 0 이상, 쿠폰·프로모션 할인 합계 |
| amount | 정수 | Y | **qty × unit_price − discount** |
| status | 코드 | Y | `PAID`, `CANCELLED`, `REFUNDED` |
| region | 코드 | Y | 서울·경기·인천·부산·대구·광주·대전·기타 |

## 2. 업무 규칙
- **매출 집계는 status = PAID 인 행만** 대상으로 한다 (재무팀 기준과 동일).
- 반품은 원주문의 status 를 REFUNDED 로 변경하는 방식이며, 음수 수량 행을 새로 만들지 않는다.
- 배치는 실패 시 해당 일자분을 **전체 삭제 후 재적재**하는 것이 원칙(운영 매뉴얼 4.2).

## 3. 현재 적재 검증 로직
- 타입 변환 실패 행만 reject (예: unit_price 가 숫자가 아님).
- 필수값 누락, 코드값 범위, 중복 키, amount 산식은 **검증하지 않음**.

## 4. 매출 대시보드 집계 방식(현행)
- `SUM(amount)` 를 order_date 기준으로 일·주 단위 합산. status 조건 없음.
- 채널별 차트는 channel 값을 그대로 그룹핑.

## 5. 최근 변경 사항
- 10/6 모바일 앱 v3.12 배포: 주문 이벤트 수집 SDK 교체(앱팀).
- 10/4 OMS 오프라인 매장(STORE) 연동 모듈 패치: 날짜 포맷 설정 일부 변경(매장 POS 2종).
- 10/2 데이터플랫폼팀 신규 입사자 2명 온보딩, 대시보드 권한 부여 절차 개편(본 이슈와 무관).

## 6. 참고
- 2026년 10월 첫 주(10/1~10/7) 대시보드 주간 매출은 재무팀 회계 마감 매출보다 **3.2% 높게** 집계됨.
